# WHAT CHANGED, AND WHAT WRONG LOOKS LIKE (2026-08-17, live bug report #964)
# The Resources zone is declared `Visibility=Self`, and GetNextTurn rendered every opponent resource
# as a CARD BACK unless the viewer OWNED it — the check was pure seat identity and nothing else.
# So "Look at all of an opponent's resources. You may play 1 of those cards for free" presented a row
# of identical card backs and asked the player to pick one BLIND. That is the bug: the reporter saw it
# as "card images do not load".
# The opponent-HAND reveal already existed (`$viewerLooksAtOppHand` scans the viewer's own pending
# decisions for a 'theirHand' param). Resources now has the exact twin, `$viewerLooksAtOppResources`
# / `$canSeeResourcesPlayer{N}`, generated by `zzGameCodeGenerator.php` beside the hand flags.
# ⚠ GENERATED FILE: the fix lives in the GENERATOR. `SWUSim/GetNextTurn.php` is regenerated and
# gitignored — never hand-patch it, and re-run `php zzGameCodeGenerator.php rootName=SWUSim` on the
# server after deploy or this reverts to card backs.
#
# WHAT TO LOOK AT, IN ORDER
#   1. BEFORE playing anything: P2's resource row is FACE DOWN (card backs) except the Credit token,
#      which is public info (CR 3.13) and has always shown face-up. If a real resource is already
#      readable here, the reveal is leaking outside its decision and that is a NEW bug.
#   2. Play Tear This Ship Apart (LAW_066) from P1's hand. The "Play one of the opponent's resources
#      for free?" prompt opens.
#   3. WHILE THAT PROMPT IS UP: every one of P2's resources must be FACE UP and readable — real card
#      art, not backs, not broken-image placeholders. This is the whole point of the fix.
#      SEC_051 Bo-Katan Kryze is deliberately in that row: she is the card from the report.
#   4. The selectable highlight must sit on the PLAYABLE resources only. The Credit token is NOT
#      playable and must not be offered (the handler filters it), though it stays face-up.
#   5. Answer or decline the prompt. P2's resources must snap BACK to card backs immediately — the
#      flag is derived from the pending decision, so it auto-clears. A row that stays face-up after
#      the decision resolves is a leak.
#   6. Look at P1's OWN resources throughout: always face-up, unchanged by any of this.
#
# THE NEGATIVE THAT MATTERS — check this as SEAT 2 as well:
#   Load the same schema viewing as P2 while P1's prompt is pending. P1's resources must stay FACE
#   DOWN to P2. The reveal is scoped to the viewer who owns the decision; if it renders for both
#   seats, the fix has become an information leak, which is strictly worse than the original bug.
#
