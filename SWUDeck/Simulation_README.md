# Saved-deck SWUSim simulation

The SWUDeck header opens `Simulation.php` in a modal through `Custom/SimulationModal.js`. The page also works directly as a standalone fallback. It reads the saved deck's current gamestate, normalizes card IDs, and calls `swuSimulationRun()` in `SimulationRuntime.php`. That function sends the deck snapshot to the protected bot endpoint on SoulMastersDB. The remote endpoint runs 1–20 independent SWUSim CLI processes in groups of four and returns aggregate results and replays. The CLI entrypoint is `SWUSim/DevTools/DeckSimulationRunner.php`. No Agentic Deckbuilder service is involved.

For the soft launch, the generated Simulate header control is shown only to a logged-in deck owner who passes `CheckLoggedInUserModStrict()`. `Simulation.php` repeats that check before serving the form, status, start, or replay actions. Hosted access uses the existing `ApprovedModeratorUserNames()` list; signed-in strict loopback requests remain available for local development. The remote bot endpoint remains protected by its separate server-to-server signature rather than a browser login.

Completed replay payloads are kept in the operating system's temporary directory for 24 hours. A replay button makes a server-side import request to the configured Petranaki-compatible host. The saved result and replay are separate from SWUStats recorded match data.

Deploy `APIs/SWUSimulation.php`, `SWUDeck/SimulationRuntime.php`, and the current `SWUSim/DevTools/DeckSimulationRunner.php` to `soulmastersdb.net`. Set the same randomly generated secret of at least 32 characters as `SWU_SIMULATION_API_SECRET` in the server environment on both hosts, or in each host's ignored `SWUDeck/SimulationConfig.local.php` as `simulation_secret`. The endpoint requires a signed request and allows two simultaneous requests. `SimulationConfig.local.php` is optional and ignored by Git. Copy `SimulationConfig.example.php` to override the bot endpoint, CLI PHP path on the bot host, or replay host. `simulation_url` defaults to `https://soulmastersdb.net/TCGEngine/APIs/SWUSimulation.php`; the caller requires HTTPS and does not follow redirects. It must be an endpoint, not the SWUSim menu page. `replay_base` remains `https://petranaki.net/TCGEngine`. Replays returned by SoulMastersDB are stored on SWUDeck's host, then imported to Petranaki only when the user opens one.

Starting a simulation closes the popup once the server has accepted it. The SWUDeck request continues with the PHP session lock released, while `SimulationJobs.php` persists the latest per-deck status and results in the operating system's temporary directory. The deck builder polls that status to update the Simulate indicator and show an in-page completion notice. The one-time background-work explanation is dismissed with “Got it!” and saved in browser local storage. A run still occupies one web request on each host; each game has a 120-second limit and at most four run at once. A 20-game batch may therefore take several minutes. Before enabling it for broad public use, add a dedicated worker queue and per-user capacity limits. The bot host's generated card dictionaries must contain every card in both decks; missing cards produce an engine error rather than a scored loss.
